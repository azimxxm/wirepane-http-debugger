## Context

- **Platform:** Electron desktop app, macOS-first. React, MobX, styled-components; tokens from [`docs/design-plan.md`](../design-plan.md).
- **Capture:** 2520×1575 PNGs with no embedded colour profile. Sampled pixels equal the CSS tokens exactly (canvas `#F4F7FB` / `#0B1220`, surface `#FFFFFF` / `#111B2E`, accent `#0F766E` / `#2DD4BF`), so no colour conversion was needed this time.
- **Coordinates** below are CSS px in the 1440×900 viewport. Multiply by 1.75 for image px.
- **States reviewed:**
  - Intercept with 2 clients (curl and a Safari/iOS user agent).
  - The iPhone setup page, waiting for a phone.
  - View in light with row 1 selected and the list focused; View in dark with nothing selected and keyboard focus on the list.
  - Modify with default rules only (one template card hovered).
  - Send with an empty new request and 3 collections.
  - Settings, top of the page; the ⌘K palette over View.
- **Not captured, so not graded:** View with 0 requests, Intercept with 0 sources (first run), the Paused state, a selected row in dark (the dark pass toggled the selection off again), Modify with an unsaved rule, Send after a response, the AI (MCP) modal, keyboard focus on the rail or a toolbar button, the real Electron window (traffic-light inset, menu bar) and the desktop default window size of 1366×768.

## 🌟 What works now

- **The app always says what it is doing.** Every screen in both themes ends in the status bar "Recording · Proxy localhost:8009 · 2 clients · Curl/8.7.1 +1 … 6 requests · 0 rules active" (12 px, 6.7:1 light, 8.8:1 dark) under a 2 px wire-gradient hairline. This fixes the root cause of the owner's complaint (baseline P0-1).
- **Every page introduces itself the same way.** A 22 px title equal to the nav label, a 13 px purpose line, actions on the right, and exactly one solid teal button per view: "View 6 requests ⌘2", "Mock response", "New rule ⌘N", "Send ⌘↵".
- **Intercept is a starting point now.** The 3-step strip shows progress (step 1 checked, step 2 is the button). Four recommended sources replace 34 cards, the manual proxy line has Copy and Set up, the rest sits behind two disclosures, and a Connected list shows who is connected.
- **The iPhone page is the best screen in the app.** Copyable server and port in 30 px mono, 6 numbered steps with the exact iOS Settings paths, a captioned QR code, a live "Waiting for your iPhone…" state and a "turn the proxy off" reminder.
- **The colour system landed exactly.** Surfaces, accent, method and status colours match the plan's hex values pixel for pixel. List selection follows the HIG: teal with white text when the list has focus (5.5:1), `#E8EDF3` with a 3 px `#78869B` bar when it doesn't (Devices panel). Hover (`#16233A`) never looks like selection.
- **Empty states point forward.** Modify opens on 6 rule templates. Send says "No response yet. Press Send or ⌘↵". View shows a key-cap cheat sheet (↑↓ or J/K, ⌘F, ⌘M, ⌘R). The Devices panel offers "Connect iPhone" and "Connect Android".
- **⌘K feels native.** Grouped commands with one-line descriptions ("Traffic keeps flowing, but View doesn't add it"), shortcuts on the right, key hints in the footer, a sky focus ring on the input, and a navy backdrop that dims the page in both themes.

## 🟠 P1

### P1-1 · View: "Resend" and "Breakpoint" lose their labels at normal window sizes, and ⌘M / ⌘R appear on none of the buttons

**Where:** `view-light.png`, detail header (x 860–1440, y 56–100).

**Problem:**

- Only "Mock response" has a label (x 1163–1300). Resend is a bare paper-plane icon (x 1307–1343), Breakpoint a bare pause-circle (x 1351–1387), More a bare chevron (x 1395–1427). None shows a shortcut.
- This is a width rule in code, but its thresholds are out of reach. `getDensity()` (`http-details-header.tsx` L30–35) hides all shortcuts below 760 px of pane width and every label except the primary one below 640 px. With the Devices panel open and the default 50/50 split, the pane is (window width − 279) / 2: 581 px at 1440 and 543 px at the 1366×768 default window. Labels only return on a 1560 px window, shortcuts on an 1800 px one.
- The tooltips don't mention ⌘M or ⌘R (the `title` strings at L277, L287, L296), and neither command exists in the ⌘K palette (`model/ui/app-actions.ts`). The shortcuts only show in the row's right-click menu and in the "nothing selected" cheat sheet, which disappears as soon as a request is selected.
- In a capture tool, a pause glyph reads as "pause recording". That is not what Breakpoint does.

**Breaks:** baseline P0-4 (the View → Modify / Send bridge must be labeled), plan rule 6, acceptance criterion "Keyboard". Recognition over recall: an unlabeled 33 px icon is a guess.

**Fix:**

- Keep both bridges labeled down to 480 px of pane width: "Mock response ⌘M" (primary) and "Resend ⌘R" (secondary). Below 640 px drop only the shortcut text, never the "Resend" label.
- Below 640 px, move "Breakpoint" into the More menu, and show More as "More ▾".
- Put the shortcut in every tooltip ("Mock this response (⌘M)", "Edit and resend in Send (⌘R)"), and add both as palette commands.
- Free up width at the same time: start the Devices panel collapsed while "This Mac" is the only device (P1-2). That takes the pane from 581 to about 680 px at 1440.

**Files:** `components/view/http/http-details-header.tsx` (`getDensity`, button titles), `model/ui/app-actions.ts`, `components/devices/devices-panel.tsx`. **Agent:** `tauri-electron-expert`.

### P1-2 · View: host names are cut to 10 characters, and the detail summary drops the path

**Where:** `view-light.png` and `view-dark.png`: the list's Host column (x 569–654) and the detail summary (x 876–1080, y 56–100).

**Problem:**

- Hosts read "jsonplaceh…" (rows 1–2) and "example.c…" (row 6). The Host column is about 85 px while Path and query gets about 175 px, because `Host` has `flex-basis: 500px` against `PathAndQuery`'s `1000px` (`event-row-components.ts` L189–199). Host always gets a third.
- The three panes split 1440 px into 215 px (Devices), 580 px (list) and 581 px (detail). With one device, the Devices panel spends its 215 px on two rows with the same count ("All devices 6", "This Mac 6") and the promo card.
- The detail summary shows "GET jsonplaceholder.typic…" and never reaches the path, so the header can't confirm which request is open.

**Breaks:** the anchor's "compact data" density and scanning. In a proxy, the host is how people tell traffic apart, and Charles and Proxyman both give it a wide column (Jakob's law).

**Fix:**

- `Host`: `flex-basis: 750px; min-width: 140px`, about 43 / 57 with Path.
- Devices panel: collapsed by default while there is one device. It expands by itself when a second device connects, and the toggle shows the device count as a badge. "Connect a phone" stays reachable from Intercept and from the status bar's clients item.
- Detail summary, path first: "GET /todos/1" in DM Mono 13/600 `textPrimary`, then the host in `textSecondary`. Ellipsize the host, not the path; the full URL stays in the tooltip (`title={request.url}` already exists).

**Files:** `components/view/event-rows/event-row-components.ts`, `components/devices/devices-panel.tsx`, `components/view/http/http-details-header.tsx` (`RequestSummary`). **Agent:** `tauri-electron-expert`.

### P1-3 · Send: the request body is hidden while an empty headers table takes ~450 px

**Where:** `send-light.png` and `send-dark.png`, the request editor (x 344–891).

**Problem:**

- "Request headers" is expanded and runs from y 137 to y 683 for a single empty row (inputs at y 197–225). About 450 px of it is blank.
- "Request body" is collapsed at y 702–731, squeezed between the headers and "Docs". The baseline asked for "Params · Headers · Body" tabs (P1-7), and that part wasn't built; there is no Params editor at all.
- Smaller issues:
  - The "Text" select (x 510–636) and the static "0 bytes" chip (x 646–715) share one `#DEE3E9` fill, so the chip looks like a second dropdown.
  - Collection names truncate ("JSONPlaceholder (cap…") while about 60 px sits unused to the right of the counts.

**Breaks:** hierarchy (the biggest area on the page is empty, and the most-used part of an API client is hidden), Jakob's law (Postman, Insomnia and Bruno all use tabs here).

**Fix:**

- Under the URL row, add a 32 px tab bar: "Params · Headers 0 · Body · Docs", 13/500, the active tab in `accent` with a 2 px underline, and counts in `textTertiary`. The default tab is Body for POST, PUT and PATCH, and Params for GET and DELETE. Each tab fills the editor height.
- Smaller interim fix: size the headers section to its rows (`flex: 0 0 auto`) and give Body `flex: 1 1 auto`, expanded by default.
- Show "0 bytes" as plain 12 px `textTertiary` text with no fill. In the collections panel, right-align the counts 16 px from the edge so the names get the space.

**Files:** `components/send/request-pane.tsx`, `components/collections/collections-panel.tsx`. **Agent:** `tauri-electron-expert`.

### P1-4 · Three inputs still use the divider colour as their border (1.1–1.4:1)

**Where:** the View filter in `view-*.png` (x 529–947, y 16–50); in `send-*.png`, "Search requests" (x 73–334, y 94–122) and the URL row (x 351–755, y 99–127).

**Problem:**

- The View filter's border is `containerBorder`: `#D5DDE8` on `#FFFFFF` (1.37:1) and `#22314A` on `#111B2E` (1.32:1), with the old inset shadow on top (`search-filter.tsx` L47–48).
- Its placeholder has no colour rule (`filter-input.tsx` L42–48), so Chrome's default `#757575` shows in both themes. On the dark field `#0D1626` that is 3.93:1.
- Send's "Search requests" uses the same border (`collections-panel.tsx` L63); `inputBorder` only appears on hover (L66).
- Send's method select and URL field have no boundary at all: `#EEF2F7` and `#F1F5F9` fills on white (1.1:1).
- The token is already right elsewhere. Intercept's search and Send's header inputs use `#78869B` / `#5F7088` (3.70:1 / 3.41:1), so this is a migration gap, not a token problem.

**Breaks:** acceptance criterion "Contrast" (the only one that fails), WCAG 1.4.11 (3:1 for input boundaries) and 1.4.3 (placeholder text), the plan's `borderControl` token.

**Fix:**

- `search-filter.tsx` L47, `filter-input.tsx` L62 and `collections-panel.tsx` L63: `border: 1px solid ${p => p.theme.inputBorder}`. Remove the inset `box-shadow` (`search-filter.tsx` L48).
- `filter-input.tsx` `::placeholder`: add `color: ${p => p.theme.inputPlaceholderColor}; opacity: 1;` (`#5E6B7E` / `#94A3B8`).
- Send URL row: a single 1 px `inputBorder` around the method and URL group, radius 6 px, with the focus ring on `:focus-within`.

**Files:** as above, plus `components/send/send-request-line.tsx`. **Agent:** `tauri-electron-expert`.

## 🟡 P2

### P2-1 · Intercept: the recommended cards don't look clickable or say what a click does

**Where:** `intercept-*.png`, the "Recommended" row (x 216–1289, y 186–334).

**Problem:**

- Each card is a 257×148 px panel with a title and a description, but no action text, no chevron, and only a decorative `#D5DDE8` border.
- Two cards act at once (Chrome opens a new browser window, Terminal opens a terminal) and two open setup guides. They look identical, so what a click does comes as a surprise.
- The Chrome, Terminal and iPhone cards are about half empty (their text ends near y 263), because the Android card's second paragraph sets the row height.
- "Fresh Terminal" is title case and upstream jargon; the other three are plain names.

**Breaks:** affordance (things you can click must look clickable), and the anchor's "the app always says what it is doing".

**Fix:**

- Add an action line at the bottom of each card in `accent`, 13/600: "Open Chrome →", "Open a terminal →", "Set up iPhone →", "Set up Android →".
- Hover: a `borderControl` border and `rowHover` fill, the same as the Modify template cards. Focus: the sky ring.
- Rename "Fresh Terminal" to "Terminal". Move Android's "Manual setup required for HTTPS in some apps" to its setup page, or show it as a 12 px `textTertiary` note, so the cards shrink to about 112 px.

**Files:** `components/intercept/guided-intercept-page.tsx`, `components/intercept/intercept-option.tsx`, `model/interception/interceptors.ts`. **Agent:** `tauri-electron-expert`.

### P2-2 · ⌘K has no on-screen entry point, and the palette ignores context

**Where:** the status bar's right side (x 1271–1423, y 872–900, every shot); `palette-*.png`; the View header buttons (x 956–1416, y 14–42).

**Problem:**

- The plan's status bar ended with "⌘K Commands" (baseline P0-1). It isn't there, so a mouse user never learns the palette exists. A browser build has no menu bar to find it in either.
- On /view with a request selected, the palette opens on "Go to Intercept". It has no request commands at all; its sections are Go, Capture, Connect, Send, View and Help (`model/ui/app-actions.ts`).
- The View header buttons show no shortcuts, while "Save… ⌘S" and "New rule ⌘N" do. Clear (⌘⇧⌫) and Import HAR (⌘O) have shortcuts that aren't shown; Export HAR and Jump to latest have none (the plan listed ⌘⇧S for Export).

**Breaks:** rule 6 (keyboard-first, shortcuts visible), consistency.

**Fix:**

- Status bar: a last item on the right, "⌘K Commands" (12/500 `textSecondary` with a key-cap chip), as a button that opens the palette.
- Palette: when a request is selected, show a "This request" group first (Mock response ⌘M, Resend ⌘R, Copy as cURL, Pin ⌘P).
- View header: show `.action-shortcut` hints on Clear and Import HAR, and give Export HAR its planned shortcut.

**Files:** `components/status-bar.tsx`, `components/command-palette.tsx`, `model/ui/app-actions.ts`, `components/view/view-toolbar.tsx`. **Agent:** `tauri-electron-expert`.

### P2-3 · Three retired colours are still on screen

**Where:** the Request pill in `view-light.png` (x 1002–1286, y 142–161); the Default rules bar in `modify-*.png` (x 104–107, y 384–422); the Terminal icon in `intercept-*.png` (x 500–530, y 203–222).

**Problem:**

- The Request pill "GET jsonplaceholder.typicode.com" is lavender `#D3C5E5` with purple `#302859` text. That is the old content-type category colour from `getSummaryColor()` (`http-request-card.tsx` L127). Everywhere else, GET is teal.
- The Default rules group's left bar is `#4CAF7D`, the pre-redesign 2xx green (2.71:1 on white).
- The Terminal icon is bright green `#1CAA0C`. That isn't a vendor colour, and it reads as "success".
- The same pane shows two different "200" pills: the header's `#157238` on `#E3EEE7`, and the response card's `#113930` on `#B8D4C3`.

**Breaks:** rule 1 (one colour, one meaning; green, amber, red and sky only for HTTP outcomes), and the plan's retirement of the 11 category colours.

**Fix:**

- Request pill: `surfaceSunken` fill and a `textPrimary` host, with the method in its method colour (GET `#0F766E` / `#5EEAD4`).
- Use one `StatusPill` (the header's) in both places.
- Default rules bar: `borderControl` (`#78869B` / `#5F7088`), or no bar at all.
- Terminal icon: `textSecondary`.

**Files:** `components/view/http/http-request-card.tsx`, `components/view/http/http-response-card.tsx`, `model/events/categorization.ts`, `components/modify/rule-list.tsx`, `model/interception/interceptors.ts`. **Agent:** `tauri-electron-expert`.

### P2-5 · The list focus ring is painted under the rows

**Where:** `view-dark.png`, the list body (x 280–858, y 94–872).

**Problem:** the 2 px `#38BDF8` ring is drawn inside the list container, and the rows paint over it. Its left and right sides only show as 4 px dashes between rows (y 124–127, 156–159, 188–191 and so on); it is solid only along the top edge and below the last row.
