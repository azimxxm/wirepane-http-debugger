## Diagnosis: why users forget what the app is for

1. **The app never states its job or its live state.** No surface says "a proxy is running on localhost:8007, it is recording, 1 client is connected, 6 requests were captured".
2. **Pages introduce themselves inconsistently.** Each page does it differently, and 2 of the 5 do not do it at all. The only reliable "you are here" cue is a 4 px orange bar on the rail.
3. **The flow's hand-offs are hidden.** The product story is Intercept → View → Modify → Send, but the links between steps are unlabeled icons and tooltip-only shortcuts. Each page feels like a separate tool.
4. **Colour has no stable meaning.** The same orange marks selection, hover, focus, "feedback", "coming soon" and the active tab. None of the UI uses the logo's navy or teal.

## 🌟 What works (keep)

- **The navigation structure is right.** The four verbs in the rail map 1:1 to the product flow, and ⌘1–⌘4 and ⌘9 are already wired (`components/app.tsx` L61–86). The fixes below change presentation and wayfinding; nothing needs rebuilding.
- **The View list has a power tool's foundations:**
  - virtualized 32 px rows (`view-event-list.tsx`, `itemSize={32}`);
  - real ARIA grid semantics (`role=grid/row/gridcell`, `aria-activedescendant`);
  - J/K and arrow-key navigation, multi-select, and ⌘[ / ⌘] to move focus between panes;
  - a native right-click menu with "Filter traffic like this", "Copy as code snippet" and "Create Matching Modify Rule".
- **Modals are built correctly.** They use native `<dialog>` with a focus trap, Esc → `onClose`, and focus restore (`common/modal.tsx`). Build the ⌘K palette on the same base.
- **The detail pane is readable.** Header tables are monospace and wrap long values (see the Report-To header at y≈805–880 in `view-light.png`), headers have inline docs, and the request and response cards collapse.
- **Accessibility work already exists:** a High-contrast theme, contrast-clamped hex colouring in Monaco (`hexColorMinContrast: 4.6`), and an `aria-label` on the Intercept search.
- **The logo is strong.** The navy tile and the teal→sky wire give a two-hue system that is easy to extend (see the colour section).

## 🔴 P0: orientation blockers

### P0-1 · Nothing tells the user what Wirepane is doing right now

**Screen:** all pages, light and dark.

**Evidence:**
- **Proxy address:** shown in one place only, a 13 px sentence in Settings → Proxy settings ("The proxy is currently using port 8007.", `settings-light.png` x739–1024, y262–275).
- **Recording state:** shown only as a 15 px pause glyph in the View list footer (x≈931–948, y≈975–992), next to four other unlabeled icons.
- **Connected clients:** listed only on the Intercept card (x1099–1638, y60–379).
- **Request count:** shown only in the View footer ("6 requests", x≈854–913, y≈971–998).

**Why it confuses:** Nielsen heuristic #1, visibility of system status. Users think of a proxy as "traffic flows through me". With no persistent signal they cannot tell whether Wirepane is working, so the app feels like a set of unrelated screens. Charles and Proxyman both keep record/pause visible in the main window at all times (Jakob's law).

**Fix:** add a global status bar on every route.
- **Size and placement:** 28 px tall, full content width to the right of the rail.
- **Style:** background `surfaceSunken`, a 1 px top border in `borderSubtle`, text 12 px/500 in `textSecondary`, items 16 px apart. Each item is a focusable button with a tooltip that shows its shortcut.
- **Left cluster:**
  - **Recording state.** Recording: an 8 px dot in `accent` plus "Recording". Paused: the dot in `textTertiary` plus "Paused — traffic still flows but isn't recorded". Clicking toggles; the shortcut is ⌘⇧R.
  - **Proxy address.** Label "Proxy localhost:8007". Clicking copies `http://localhost:8007` and shows the toast "Proxy address copied".
  - **Clients.** "1 client · curl/8.7.1". With no clients: "No clients yet — Connect a source ⌘1", linking to /intercept.
- **Right cluster:**
  - "6 requests", linking to /view.
  - "2 rules active", linking to /modify.
  - "⌘K Commands".
- **Hairline:** while recording, a 2 px top hairline in the wire gradient `linear-gradient(90deg,#2DD4BF,#38BDF8)`. While paused, the hairline is `borderSubtle`.
- **Single control:** the status bar becomes the only pause control. Remove `RequestCounter` and `PlayPauseButton` from the View footer.

```
+------+--------------------------------------------------------------------------+
| logo | Intercept                                            [View 6 requests ⌘2] |  PageHeader 56px
|      | Connect a browser, terminal, phone or container so its HTTP(S) ...        |
| Int  +--------------------------------------------------------------------------+
| View |                                                                          |
| Mod  |                         page content                                     |
| Send |                                                                          |
|      +--------------------------------------------------------------------------+
| Set  | ● Recording · Proxy localhost:8007 · 1 client (curl) |  6 requests · 0 rules · ⌘K |  StatusBar 28px
| AI   |                                                                          |
+------+--------------------------------------------------------------------------+
```

**Files:**
- new `src/components/status-bar.tsx`;
- `src/components/app.tsx`: wrap `<Router>` and `<StatusBar/>` in a flex column;
- data sources: `model/proxy-store.ts` (port), `model/events/events-store.ts` (`isPaused`, `togglePause`, `activeSources`, event count), `model/rules/rules-store.ts`;
- `view/view-event-list-footer.tsx` and `view/view-event-list-buttons.tsx`: remove the counter and the pause button.

### P0-2 · Intercept is a catalog, not a starting point

**Screen:** /intercept, light and dark.

**Evidence:**
- **Option count.** There are 34 interceptors (`model/interception/interceptors.ts`), all shown as equal-weight 238×200 cards. The first viewport holds 12 of them. Two of those 12, "Attach to Docker Container" and "Chrome (Beta)" (y≥922), are disabled and shown at 50% opacity.
- **Empty hero.** The right half of the hero is the 540×320 "Connected sources" card (x1099–1638, y60–379). It holds one line, "? Curl/8.7.1". On first run it is completely empty (`logs/verify-ui.png`).
- **Text before action.** A 38 px H1 and two 20 px paragraphs (7 lines) come before any action.
- **Wrong icon.** The universal "Anything" option uses the "?" icon.

**Why it confuses:**
- **Hick–Hyman.** Choosing among 34 options costs log2(35) ≈ 5.1 bits. Four recommended options plus "More" cost log2(6) ≈ 2.6 bits, about half the decision time.
- **No anchor.** There is no single primary call to action, and the most prominent block is the empty card, which says nothing.
- **No next step.** The page never says what happens after you connect, so the View / Modify / Send story is missing.

**Fix:** rebuild the page in this order, top to bottom, with max-width 1120 px.
1. **PageHeader** (see P0-3).
   - Title: "Intercept".
   - Purpose line: "Connect a browser, terminal, phone or container so its HTTP(S) traffic flows through Wirepane."
2. **"How it works" strip.** One row, 64 px: "(1) Connect a source → (2) Inspect traffic — View ⌘2 → (3) Mock or replay — Modify ⌘3 · Send ⌘4".
   - The current step gets a 24 px `accent` badge.
   - Once `activeSources.length > 0`, step 1 shows a check mark and step 2 turns into the primary button "View 6 requests".
3. **"Recommended" row.** Four cards in one row:
   - `fresh-chrome`;
   - `fresh-terminal`;
   - `manual-ios-device`, titled "iPhone or iPad";
   - `android-device`, titled "Android (QR code)".
   - Card spec: 24 px icon at top left, 16 px/600 title, 13 px description, no watermark.
4. **Manual setup line.** A single text row: "Any other app: set its proxy to localhost:8007 [Copy] and trust the Wirepane CA [Set up]". The "[Set up]" link opens `manual-setup`.
5. **Search and the rest.**
   - Search field with the placeholder "Search 30 more sources — Firefox, Docker, JVM, Electron, Frida…".
   - Below it, a collapsed disclosure "More sources (N)".
   - Unavailable and "Coming soon" options go in a second disclosure, "Not available on this Mac (N)".
6. **"Connected" list.**
   - Render it only when at least one source is connected.
   - One 32 px row per client ("curl/8.7.1 · last request 2s ago") plus a "View requests ⌘2" button.
   - Remove the fixed 320 px grid row.

```
Intercept
Connect a browser, terminal, phone or container so its HTTP(S) traffic flows through Wirepane.

(1) Connect a source  -->  (2) Inspect traffic  View ⌘2  -->  (3) Mock or replay  Modify ⌘3 · Send ⌘4

Recommended
[ Chrome          ] [ Terminal        ] [ iPhone or iPad  ] [ Android (QR)    ]
Any other app: proxy localhost:8007 [Copy] · trust the Wirepane CA [Set up]
[ Search 30 more sources: Firefox, Docker, JVM, Electron, Frida... ]
> More sources (24)        > Not available on this Mac (6)
Connected: curl/8.7.1 · last request 2s ago                      [View requests ⌘2]
```

**Files:**
- `intercept/intercept-page.tsx`: grid at L26–58, copy at L167–183;
- `intercept/connected-sources.tsx`;
- `intercept/intercept-option.tsx`: `BackgroundIcons` at L62–80, status pills;
- `model/interception/interceptors.ts`: add a `RECOMMENDED_INTERCEPTOR_IDS` list.

**Target agent:** `tauri-electron-expert`

### P0-3 · Every page introduces itself differently, and two don't at all

**Screen:** all routes, light and dark.

**Evidence:**
- **Intercept:** "Intercept HTTP" in DM Sans at 38 px, inside a 2-column hero (x521–778, y69–104).
- **Modify:** "Transform & Mock HTTP" at 38 px, in a toolbar strip (x116–534, y24–52). The title does not match the rail label "Modify".
- **Settings:** "Settings" in Saira, a third font family, at 38 px in a centred column (x721–861, y44–79).
- **View and Send:** no title at all.
- **Card headings repeat the problem inside pages.** "PROXY SETTINGS", "CONNECTED SOURCES", "REQUEST" and "RESPONSE" are right-aligned, uppercase and grey.

**Why it confuses:** Users look for "you are here" where the F-pattern starts, at the top left. The label there should match the nav item the user just clicked (consistency and standards; recognition rather than recall). Right now the only stable cue is a 4×72 px orange bar on the rail (x71–74, y151–222).

**Fix:** add one `PageHeader` component and use it on every route.
- **Size:** 56 px tall, padding 0 24 px, background `surface`, 1 px bottom border in `borderSubtle`.
- **Left side:** the title in 22 px/600 `textPrimary`, exactly matching the nav label. Under it, a one-line purpose in 13 px `textSecondary`, ellipsized if too long.
- **Right side:** the page's actions.
- **Purpose copy per page:**
  - Intercept: "Connect a browser, terminal, phone or container so its HTTP(S) traffic flows through Wirepane."
  - View: "Every request that passes through Wirepane. Select one to inspect it."
  - Modify: "Rules change matching traffic as it passes through: mock, rewrite, delay, breakpoint, map local or remote."
  - Send: "Build a request or paste a cURL command. Resend captured requests from View with ⌘R."
  - Settings: "Proxy port, certificates, upstream proxy and appearance."
- **View variant.** On View the header doubles as the list toolbar, so it costs no extra height. It holds:
  - the title;
  - the filter field, moved up from the bottom;
  - Clear, Jump to latest, Import HAR and Export HAR as 28 px icon+label buttons.
  - Pause lives in the status bar.
- **Window title.** Set `document.title` to "View — Wirepane" (and the same pattern on every page), so the macOS window title, Window menu and Mission Control follow the current page.

**Files:**
- new `src/components/common/page-header.tsx`;
- `intercept/intercept-page.tsx` (`InterceptInstructions`);
- `modify/modify-page.tsx` (`ModifyPageHeader` and `EditHeading`, L54–71 and L157);
- `settings/settings-page.tsx` (`SettingsHeading`, L43–48);
- `send/send-page.tsx`;
- `view/view-page.tsx` and `view/view-event-list-footer.tsx`.

**Target agent:** `tauri-electron-expert`

### P0-4 · The hand-offs from View to Modify and Send are hidden

**Screen:** /view with a request selected. Seen in light; the same code renders dark.

**Evidence:**
- **On screen.** The only visible ways to "mock this" or "resend this" are two unlabeled Phosphor glyphs, a pencil and a paper plane. They sit at the bottom centre of the detail pane in a 144×14 px cluster of five icons, next to eye, pin and trash (`view-light.png` x1522–1666, y974–988).
- **Shortcuts.** ⌘M, ⌘R, ⌘P and ⌘⌫ exist (`view-page.tsx` hotkeys), but they appear only in `title` tooltips.
- **Context menu.** The native context menu has "Resend Request" and "Create Matching Modify Rule", but shows no accelerators. `view-context-menu-builder.ts` never sets `accelerator`, even though the desktop bridge supports it (`httptoolkit-desktop/src/context-menu.ts` L19 and L76).

**Why it confuses:**
- **These are the bridges.** They are what turn the four nav items into one product.
- **Fitts' law.** From the selected row (≈380, 54) to the pencil (≈1631, 981), the distance is ≈1557 px to a ≈30 px target: an index of difficulty of ≈5.7 bits. A 150 px labeled button at the top of the detail pane brings that down to ≈3.3 bits.
- **Mixed icon styles.** The cluster mixes FontAwesome solid (eye, pin), FontAwesome regular (trash) and Phosphor outline (pencil, plane).

**Fix:** replace `HttpDetailsFooter` with a sticky detail header.
- **Container:** 44 px tall, background `surface`, bottom border in `borderSubtle`.
- **Left side:** a one-line request summary.
  - The method in DM Mono 13 px/600, in its method colour.
  - Then host and path in DM Mono 13 px `textPrimary`, ellipsized.
  - Then a status pill, "200 OK".
- **Right side:** 28 px icon+label buttons (13 px/500, Phosphor regular icons at 16 px):
  - "Mock response ⌘M": the primary button, `accent` fill with `textOnAccent` text.
  - "Resend ⌘R".
  - "Breakpoint": wire this to the existing `createRuleFromRequest` (`http-details-pane.tsx` L500–506).
  - "More ▾": Copy as cURL, Pin ⌘P, Scroll to row, Delete ⌘⌫.
- **Context-menu accelerators:**
  - Add `CmdOrCtrl+R`, `CmdOrCtrl+M`, `CmdOrCtrl+P` and `CmdOrCtrl+Backspace` to the matching options.
  - Extend the UI-side menu item type so it can carry them.
- **Empty detail state:** see P1-7.

**Files:**
- `view/http/http-details-footer.tsx`, replaced by a new `http-details-header.tsx`;
- `view/http/http-details-pane.tsx`;
- `view/view-context-menu-builder.ts`;
- the UI `ContextMenuItem` type.

**Target agent:** `tauri-electron-expert`

## 🟠 P1: major issues

### P1-1 · Colour carries no stable meaning, and none of it is the brand

**Screen:** all, light and dark.

**Evidence:**
- **One orange, many jobs.** `popColor #E1421F` is a single constant with 50 references in 27 files. It colours:
  - the active nav bar, and nav items on hover and on focus;
  - the "Give feedback" item;
  - the active Send tab underline;
  - card titles while the card has focus;
  - the "Coming soon" pill;
  - the list's focus outline;
  - the icon for requests sent from Send (`model/http/sources.ts` L158).
- **Indigo.** Primary buttons and the Modify "import" icon use `#2D4CBD`.
- **Unexplained category bars.** Row category bars use 11 hard-coded colours (`model/events/categorization.ts` L170–182), with no legend.
- **No brand colour.** The only teal or navy anywhere in the UI is the 44 px logo.
- **States look identical.** In `intercept-light.png`, "MCP" (x23–51, y861–912) is orange too, because the pointer or focus was on it at capture time. Hover, focus, selection and "feedback" look exactly alike.

**Why it confuses:** Gestalt similarity: the same colour reads as the same meaning. Users cannot tell "where I am" from "what I'm pointing at" from "a link out of the app". The owner's brand request is also unmet.

**Fix:** adopt the token system in the colour section below.
- **One meaning per colour:**
  - teal means action and selection;
  - sky means keyboard focus;
  - semantic green, amber, red and sky are used only for HTTP outcomes;
  - the navy tile gradient is reserved for app chrome (the rail and the modal backdrop).
- **Retire** `#E1421F` and `#2D4CBD` entirely.
- **Make `popColor` per-theme** instead of an exported constant, and update its 3 direct imports:
  - `model/http/sources.ts`;
  - `intercept/intercept-option.tsx`;
  - `account/pro-placeholders.tsx`.

**Files:** `src/styles.ts` (L28–46, both themes and the HC theme), the 3 files above, and `model/events/categorization.ts`.

**Target agent:** `tauri-electron-expert`

### P1-2 · "Give feedback" is the loudest item in the navigation

**Screen:** all, light and dark.

**Evidence:**
- **Styling.** The rail item renders in `popColor` and bold (`highlight: true`, `app.tsx` L195–203) at x7–66, y933–991. It is the only coloured label in the rail.
- **Contrast.** 4.02:1 on `#FAFAFA` (light) and 2.96:1 on `#32343B` (dark). At 14.5 px with synthesized bold, it fails AA 4.5:1 in both themes.
- **Two destinations.** The rail item goes to `github.com/azimxxm/wirepane`, while Help → "Share Your Feedback" goes to `github.com/httptoolkit/httptoolkit` (`httptoolkit-desktop/src/menu.ts` L77).

**Why it confuses:** the Von Restorff effect: the one coloured item is the one people notice and remember. Here that item is a link out to GitHub, not a step in the workflow.

**Fix:**
- Remove `highlight`.
- Render the item as a 20 px neutral, icon-only button with the tooltip "Send feedback".
- Add "Report an Issue…" to the Help menu.
- Point both entries at the same URL.

**Files:** `components/app.tsx`, `components/sidebar.tsx` (`SidebarLink` highlight CSS at L115–135), `httptoolkit-desktop/src/menu.ts`.

**Target agent:** `tauri-electron-expert`

### P1-3 · HTTP status colours fail AA exactly where users look

**Screen:** /view list and detail pills. 2xx and 4xx fail in light; 5xx fails in dark.

**Evidence:** `getStatusColor` (`categorization.ts` L218–236) returns:

### P1-4 · The selected request is almost invisible, and selecting it erases its status colour

**Screen:** /view. Seen in light; the dark case follows from the code.

**Evidence:**
- **How the selected row differs.** Row 1 (y≈38–70) differs from the others only by:
  - a background of `#FFFFFF` instead of `#FAFAFA` (1.04:1);
  - a synthesized-bold weight;
  - a black marker.
- **Colour is wiped.** `EventListRow.selected` forces every child element to `highlightColor`, so the green "200" turns black (`event-row-components.ts` L58–69).
- **Keyboard focus.** Focus is a 1 px dotted orange line (`view-event-list.tsx` L85–93).
- **Dark.** The selected row is `#53565E` against a row colour of `#32343B`: 1.69:1.

**Why it confuses:**
- **Users can't tell which request the right pane shows.** This fails WCAG 1.4.11, which requires 3:1 for state indicators.
- **It isn't native.** Apple's HIG (Focus and selection) says macOS "draws focused list items using white text and a background highlight that matches the app's accent color, drawing unfocused items using the standard text color and a gray background highlight".

**Fix:**
- **Focused and selected** (the grid has `:focus-within`): background `selectionBackground #0F766E` with all text `#FFFFFF` (5.5:1). The row stands out from the surface at 5.5:1 in light and 3.1:1 in dark.
- **Unfocused and selected:**
  - background `#E8EDF3` (light) or `#22314A` (dark);
  - method and status keep their colours;
  - add a 3 px inset leading bar via `box-shadow: inset 3px 0 0 …`, in `#78869B` (light) or `#5F7088` (dark).
- **Hover:** `#F1F5F9` (light) or `#16233A` (dark).
- **Remove `font-weight: bold`** from `.selected`, because synthesized bold shifts the column text.
- **Replace the dotted outline** with the selection fill.

**Files:**
- `view/event-rows/event-row-components.ts`;
- `view/view-event-list.tsx`;
- `src/styles.ts`: add new `selection*` keys. Leave `highlightBackground` alone, because 7 other components use it.

**Target agent:** `tauri-electron-expert`

### P1-5 · Keyboard focus is hidden across the app

**Screen:** all, light and dark.

**Evidence:**
- **Outlines removed.** There are 29 `outline: none` declarations across 23 files (sidebar, icon-button, close-button, inputs, card, tabbed-options, send-request-line, mcp-modal, and more), plus a global `:active { outline: none }` (`styles.ts` L322–324). Only 3 `:focus-visible` rules exist.
- **Colour-only focus.** Focus usually shows only as the glyph turning orange. Examples: the sidebar's `&:hover, &:focus { outline: none; color: popColor }` (`sidebar.tsx` L89–93) and `icon-button.tsx` L48–53.
- **Dark input borders.** In dark, input borders are `#53565E` on card `#32343B` (1.69:1), so fields barely read as fields. See the Settings port inputs at x≈882–958, y≈183–250.

### Usage rules

1. **One colour, one meaning.**
   - Teal means "act" or "selected".
   - Sky means keyboard focus.
   - Navy is app chrome.
   - Green, amber, red and sky are used only for HTTP outcomes.
2. **Hover and selection never share a colour.** Hover uses `rowHover` or a text-colour shift; selection uses the accent fill.
3. **At most one solid-accent button per view**, for the primary action. Every other button is either secondary (`borderControl` outline with `textPrimary` text) or ghost.
4. **The wire gradient appears at most once per screen**, as the recording hairline or the active-nav bar, and never behind text.
5. **High-contrast theme.** Keep its black and white surfaces, and take the dark theme's accent, focus and status values; all of them are ≥7:1 on `#000`.

## Top 5 fixes, ranked by impact on "users forget what the app is for"

1. **Global status bar (P0-1).** "Recording · Proxy localhost:8007 · 1 client · 6 requests · ⌘K", on every page, with record/pause in one place. This is the app saying what it is and that it is working, all the time. Files: new `status-bar.tsx`, `app.tsx`.
2. **Intercept as a guided start (P0-2).** A 3-step "Connect → Inspect → Mock or replay" strip, 4 recommended sources, the manual proxy line, and "More sources" collapsed. It cuts the first decision from about 5.1 to 2.6 bits and teaches the whole flow on the first screen. Files: `intercept-page.tsx`, `connected-sources.tsx`, `intercept-option.tsx`, `interceptors.ts`.
3. **One `PageHeader` everywhere (P0-3).** The title equals the nav label, followed by a one-line purpose and the page's actions. View and Send get titles, Modify stops being "Transform & Mock HTTP", and the window title follows the page. Files: new `page-header.tsx` plus the 5 page components.
4. **A detail-pane action header in View (P0-4).** "Mock response ⌘M", "Resend ⌘R" and "Breakpoint" as labeled buttons, with accelerators in the context menu. This makes View → Modify → Send one visible path. Files: `http-details-pane.tsx`, a new `http-details-header.tsx`, `view-context-menu-builder.ts`.
5. **Purposeful empty states (P1-7).** Modify gets a template grid and a "New rule" button; Send gets a response placeholder and Params/Headers/Body tabs; View gets a "Connect a source ⌘1" empty state and a shortcut cheat sheet. Files: `modify-page.tsx`, `rule-row.tsx`, `response-pane.tsx`, `request-pane.tsx`, `view-page.tsx`, `view-event-list.tsx`, `empty-state.tsx`.
